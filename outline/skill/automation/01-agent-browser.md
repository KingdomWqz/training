# 第 5 课：Agent Browser：网页任务自动化与验证（30 分钟）

## 课程定位

面向需要重复检索、录入、核对或测试网页流程的学员。课程讲解如何将网页任务拆成可靠步骤，并在自动化前后设置验证与人工确认点。

## 教学目标

完成本课后，学员能够：

1. 判断一个网页任务是否适合自动化。
2. 将任务拆成前置条件、操作步骤、预期结果和异常处理。
3. 使用稳定定位、显式等待和结果校验降低失败率。
4. 为高风险操作设置人工确认和可追溯记录。

## 核心内容

### 一、适用范围

适合自动化：公开信息检索、固定表单预填、网页回归测试、重复数据核对和页面截图检查。

不应直接自动化：支付、不可撤销发布、账号授权、绕过访问控制、处理未获授权的个人数据，以及需要主观判断的最终决策。

### 二、网页任务流程卡

~~~text
任务目标：
前置条件：账号、权限、输入数据、页面状态。
操作步骤：每一步只做一个页面动作。
预期结果：页面上可观察到的文本、状态或文件。
异常处理：超时、登录失效、元素不存在时如何停止。
人工确认点：提交、发布、删除或外发之前。
执行记录：时间、输入、结果截图或日志。
~~~

### 三、可靠执行原则

- 以页面语义、可见文字和稳定属性定位元素，少依赖易变的坐标。
- 等待页面真正进入目标状态后再执行下一步，不以固定延时替代验证。
- 操作后检查结果；对可能重复执行的操作设置幂等保护。
- 将敏感输入放在受控环境中，不把令牌、密码或个人数据写入任务说明和日志。

## 课堂演示

以“打开公开文档、搜索一个关键词、提取标题并截图留存”为例，展示任务流程卡、执行过程、结果校验和失败后的人工处理方式。

## 学员实践

为一个低风险、可重复的网页任务写流程卡，至少包含 3 个操作步骤、2 个验证点和 1 个异常处理方案。

## 课后作业

在测试环境或公开页面完成一次自动化任务，并提交流程卡、执行结果与失败复盘。涉及提交、发布或删除的步骤必须改为“等待人工确认”。

## 教学准备清单

- [ ] 准备一个无需登录的公开网页任务。
- [ ] 准备一个元素加载失败或页面状态变化的演示案例。
- [ ] 准备任务流程卡、执行记录和风险确认清单。
