# 第 1 课：任务提示词与上下文设计（30 分钟）

## 课程定位

面向需要用 AI 完成写作、分析、开发或内容制作任务的学员。课程建立一套可复用的任务描述方法，让 AI 获得足够、准确且不过量的上下文。

## 教学目标

完成本课后，学员能够：

1. 区分“聊天式提问”和“可执行任务”。
2. 用目标、上下文、约束、交付和验收五部分描述任务。
3. 通过追问、样例和验收标准提高输出稳定性。
4. 将高频任务整理为可复用 Prompt 模板。

## 时间安排

| 环节 | 时长 | 内容与产出 |
| --- | ---: | --- |
| 场景导入 | 3 分钟 | 对比模糊需求与可执行任务 |
| 任务结构 | 8 分钟 | 学习五段式任务模板 |
| 上下文与约束 | 7 分钟 | 判断该给什么、不该给什么 |
| 课堂演示 | 5 分钟 | 将一个需求迭代成可交付结果 |
| 动手实践 | 5 分钟 | 为自己的任务写 Prompt |
| 回顾与作业 | 2 分钟 | 固化模板与改进点 |

## 核心内容

### 一、五段式任务模板

~~~text
目标：要解决什么问题，服务谁。
上下文：已有资料、现状、术语和参考样例。
约束：范围、格式、风格、时间、不能做什么。
交付：最终需要的文件、结构或清单。
验收：如何判断结果合格，需要自检哪些项。
~~~

### 二、上下文选择原则

- 先提供会改变答案的事实，如目标用户、技术栈、原文和已有决定。
- 用文件、表格、示例或明确边界替代“按常规处理”等模糊表达。
- 不提供无关历史、敏感信息或未经确认的假设。
- 长任务拆成“澄清 -> 方案 -> 执行 -> 检查”四步，每一步都保留可验证产物。

### 三、验收先行

在任务开始前写出检查项，例如“链接可打开、移动端不溢出、结论附来源、代码可通过测试”。验收项既是 AI 的工作边界，也是人工复核清单。

## 课堂演示

以“整理一份课程活动页”为例，先输入“帮我做一个课程页面”，再补充目标受众、已有资料、页面模块、视觉限制和验收清单。对比两次输出的结构、遗漏项和可执行性。

## 学员实践

选择一个本周真实任务，使用五段式模板完成任务说明，并让 AI 输出：

1. 对任务理解的复述与待澄清问题。
2. 分步执行方案。
3. 一个符合验收项的初稿。

## 课后作业

将本课 Prompt 保存为个人模板；一周内在三个不同任务中复用，并记录哪些上下文最有价值、哪些约束需要补充。

## 教学准备清单

- [ ] 准备一组模糊需求与一组完整需求。
- [ ] 准备一个包含目标、资料和验收标准的真实案例。
- [ ] 准备可供学员改写的五段式模板。
