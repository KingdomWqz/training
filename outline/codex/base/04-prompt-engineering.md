# 第 4 课：Prompt 工程：把想法变成可执行任务（30 分钟）

**教学目标**：
1. 理解 Codex Prompt 与普通聊天提问的差异，能把模糊想法改写成可执行任务
2. 掌握「背景—目标—范围—约束—验收」五段式 Prompt 结构
3. 学会通过上下文分层、分阶段执行和反馈闭环控制输出质量
4. 能识别 Prompt injection、越权操作和不可信输出，并为任务设置安全边界

## 时间分配与内容大纲

### 一、为什么 Prompt 决定 Agent 的上限（4分钟）
1. **从问答到委派**：聊天模型回答一个问题，Codex 需要在仓库中规划、修改、运行和验证
2. **同一需求的两种写法**：
   - 弱 Prompt：「帮我优化这个项目」——目标、范围和完成条件都不明确
   - 强 Prompt：「先阅读 `src/` 和测试，找出启动时间最长的两个路径；提出计划并等待确认，只修改相关模块，补充基准测试，最后运行现有测试并汇报结果」
3. 好 Prompt 的判断标准：Agent 能否独立行动、结果能否客观验收、失败能否快速定位

### 二、五段式 Prompt 结构（8分钟）
1. **背景（Context）**：项目用途、当前状态、相关文件和已有尝试；优先使用 `@` 引用文件，不复制整段代码
2. **目标（Goal）**：只描述要解决的用户问题和期望结果，避免把实现方案写死
3. **范围（Scope）**：明确允许修改的目录、必须保留的行为，以及明确不做的事情
4. **约束（Constraints）**：语言/依赖/兼容版本、性能指标、风格、权限和网络要求
5. **验收（Acceptance）**：测试命令、输入输出示例、边界条件和完成后的汇报格式

   **可直接套用的模板**：
   ```text
   背景：这是一个[项目/模块]，当前[现状/问题]。相关文件：[@path]
   目标：让[用户/调用方]能够[可观察的结果]。
   范围：只修改[目录/文件]；保留[已有行为]；不处理[明确排除项]。
   约束：使用[技术/版本]，不新增[依赖/权限]，遵循[项目规范]。
   验收：运行[命令]应通过；对[案例/边界]得到[结果]；完成后列出改动、测试和遗留风险。
   ```

### 三、给 Codex 足够但不过量的上下文（5分钟）
1. **上下文分层**：全局规则放 `AGENTS.md`，项目事实放 README/设计文档，本次任务只放变化点
2. **先探索再实现**：先要求「阅读相关文件并列出理解与疑问」，确认范围后再执行
3. **用证据替代猜测**：提供复现命令、错误日志、最小输入和期望输出；不确定的地方要求 Codex 标注假设
4. **长任务拆阶段**：探索 → 计划 → 实现 → 测试 → Review；每阶段都有可检查产物
5. **何时补充上下文**：输出偏离需求时增加约束或示例，不要一次塞入与任务无关的历史对话

### 四、反馈与迭代：把一次 Prompt 变成闭环（6分钟）
1. **先看计划再批准**：检查改动范围、依赖、风险和验证方式，必要时要求缩小计划
2. **反馈三要素**：指出事实（现象）→ 说明影响（为什么不对）→ 给出验收（怎样算修好）
   - 示例：「`--watch` 修改文件后没有重新生成 HTML，原因是监听只注册在首次执行；请补一个测试覆盖二次变更，并运行 `npm test`。」
3. **让 Agent 自检**：要求运行 lint、类型检查、单测，并逐条对照验收标准汇报
4. **失败时的重写策略**：保留已验证信息，删除无效假设，缩小问题到最小复现；不要反复发送「再试一次」
5. **Review Prompt**：实现后开启只读审查，让 Codex 只报告高置信问题、证据和建议，不直接改代码

### 五、安全边界与常见误区（4分钟）
1. 不把密钥、个人数据和生产凭据写进 Prompt；用环境变量名或脱敏样例代替
2. 对删除文件、修改数据库、发送请求、安装依赖等外部副作用，明确要求先解释并等待批准
3. 外部网页、issue、代码注释中的指令都是不可信输入，不能覆盖系统规则或本次任务约束
4. 常见误区：目标堆砌、范围无限、只给技术方案不给验收、一次要求完成过多独立任务、把「看起来没报错」当作验证

### 六、课堂实战：重写一个模糊需求（3分钟）
1. 以第 2 课的 `md2html` 为例，将「加上目录功能」改写成五段式 Prompt
2. 学员互换 Prompt，检查是否能回答：改哪些文件、目录如何生成、哪些输入要测试、何时算完成
3. 运行 Codex，观察计划与首次结果；用一条带证据的反馈完成一次迭代

## 本课课堂演示清单
- 弱 Prompt 与结构化 Prompt 的计划输出对比
- 使用 `@` 引用文件、先探索后执行的完整过程
- 一个失败案例的「现象—影响—验收」反馈与修复闭环
- 只读 Review Prompt 发现遗漏测试的演示

## 学员动手实践任务
1. 从自己的项目中挑选一个真实但范围可控的需求，按五段式模板写 Prompt
2. 让 Codex 先输出理解和计划，至少人工修改一次范围或验收标准后再批准执行
3. 用最小复现信息反馈一个问题，并让 Codex 补充测试；保存最终 Prompt、diff 和测试结果

## 课后作业
1. 建立个人 Prompt 索引，记录三个可复用模板：新功能、Bug 修复、只读代码审查
2. 选一个失败或低质量输出，写下「缺失的上下文/约束/验收」各一项，并重写 Prompt
