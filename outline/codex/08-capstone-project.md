# 第 8 课：综合实战——从零构建完整产品（30 分钟）

**对应教材**：《OpenAI Codex 从入门到精通》§09 从零构建一个完整产品、§10 双线开发者的心智模型
**教学目标**：
1. 综合运用前七课全部技能（Plan 模式 → AGENTS.md → Worktree 并行 → /review 质量把关 → 云端异步收尾），交付完整 Web 应用
2. 掌握多 Agent 并行开发的「先约定接口、各做各的、最后拼装」方法论
3. 建立「AI 能写代码，但你得知道要什么」的产品判断意识
4. 理解 Codex 与 Claude Code 的组合策略，形成自己的双工流心智模型

## 时间分配与内容大纲

> **组织提示**：本课课堂以五阶段路线图的推演与关键决策点讲解为主，完整的动手开发作为课后毕业实战延续推进。

### 一、项目发布与全局规划（5分钟）
1. **实战项目公布：AI 文章摘要工具**——粘贴 URL → 抓取正文 → 生成三档摘要（一句话/短/详细）→ 存历史记录
2. **选型理由讲解**：前端 Next.js 15 + Tailwind / 后端 API Routes / SQLite + Drizzle ORM / 部署 Vercel——四层技术覆盖面刚好，且三层可独立并行
3. **阶段路线图**（呼应课程主线）：
   - 阶段一 Plan 模式规划（CLI）
   - 阶段二 Full Auto 基础搭建（CLI）
   - 阶段三 三 Agent 并行开发（App + Worktree）
   - 阶段四 合并与 /review 测试（CLI）
   - 阶段五 异步优化与部署（Cloud）

### 二、阶段一二：Plan 规划与骨架搭建（6分钟）
1. **Plan 模式发需求**：Shift+Tab 进入计划模式，产出技术方案与项目结构
   - 追问示范：「Cheerio 能处理 JS 渲染页面吗？微信文章怎么办？考虑 Vercel 部署限制」——追问力 = 判断力的体现
2. **生成 AGENTS.md**：全局一份 + src/app 前端版 + src/lib 后端数据库版；把接口契约全部写进去（本课成败关键，第 4 课技能直接应用）
3. **Full Auto 初始化骨架**：create-next-app + 依赖安装 + Drizzle Schema + 最简首页
4. **两条纪律**：
   - 骨架跑通 `npm run dev` 验证后立刻 commit——「每个里程碑都 commit 是保险不是洁癖」
   - 不给 AI 太大的任务：任务越具体输出越可控

### 三、阶段三：三 Agent 并行开发（7分钟）
学员分组跟做（讲师演示节奏）：
1. **开三个 Worktree 任务**（先约定接口再开工）：

   | Agent | 分支 | 范围 | 关键约定 |
   |-------|------|------|----------|
   | 1 | feat/frontend-ui | 全部页面组件 | 用 mock 数据；调用 POST /api/summarize、GET /api/history 等约定接口 |
   | 2 | feat/backend-api | API+抓取+摘要生成 | 数据库操作只走 src/lib/db.ts 暴露的函数 |
   | 3 | feat/database | Schema+迁移+CRUD | CRUD 函数签名先行确定 |

2. **等待期的正确姿势**：准备 .env.local（OPENAI_API_KEY）/ 先审最完成度高的库（通常 database 最快出）/ 备好 Vercel 项目配置
3. **花叔经验强调**：并行最容易翻车的不是代码是「接口不一致」——10 分钟的约定省 1 小时的对齐

### 四、阶段四：合并集成与质量把关（6分钟）
1. **合并顺序有讲究**：底层优先——database → backend-api → frontend-ui
2. 冲突处理交给 Codex 并给出仲裁原则：「数据库层以 feat/database 为准，API 层以 feat/backend-api 为准」
3. **典型四类问题对照表**（教材 §09）：类型不匹配 / 导入路径错误 / 环境变量硬编码 / 数据库连接重复——统一以 AGENTS.md 契约为准修复
4. `/review` 全项目审查 + 端到端测试清单驱动验证（正常流程 + 边界情况都要测）
5. 通过后 commit + tag v0.1.0

### 五、阶段五：云端异步收尾与部署（2分钟要点式）
1. 三类收尾任务批量丢 Cloud：README 编写 / 错误处理优化 / SEO 性能优化——并行独立容器各出 PR
2. Vercel 部署要点 + SQLite 持久化局限说明（Serverless 冷启动丢文件 → Turso 迁移思路）

### 六、常见陷阱总览与方法论沉淀（2分钟）
1. 教材八大陷阱速过（重点前三）：
   - Agent 改了不该改的文件 → worktree 隔离 + 合并时人工审查
   - 多 Agent 改同一配置冲突 → 共享配置文件只由一个 Agent 负责
   - 云端任务起不来 → setup 写全依赖；描述比本地详细 2~3 倍
2. **三条核心原则总结**（要求学员记笔记）：
   - 不要一次给 AI 太大的任务
   - 每一步都验证，出了问题再回头查成本更高
   - 最重要的能力不是写 prompt，是判断 AI 输出质量

### 七、双线开发者心智模型与结课（2分钟延伸）
1. 破除误解：Claude Code 也是多形态系统，差异在模型选型与生态侧重而非形态数量
2. benchmark 诚实解读：Codex 强在终端任务（Terminal-Bench 82.7% vs 69.4%）；Claude 强在真实 GitHub issue（SWE-Bench Pro 64.3% vs 58.6%）；1M 上下文都不是免费午餐（MRCR 检索率大幅下滑的诚实事实）
3. 双工流分工口诀：**Codex for keystroke（想清楚的快速执行），Claude Code for commits（没想清楚的一起想）**
4. 成本策略回顾：日常 GPT-5.4，关键任务 GPT-5.5；警惕 xhigh reasoning 默认档烧配额
5. 结课寄语：工具会换、模型会变，为自己积累的工作方法属于你自己；所有内容以官方 Changelog 为准持续更新认知

## 本课课堂演示清单
- Plan 模式产出方案到 AGENTS.md 定稿的完整链路
- 三 worktree 创建 → 并行进度监控 → 逐个回收合并实录（压缩演示）
- 合并后第一轮 `/review` 的真实输出讲解

## 学员动手实践任务（课后毕业实战延续完成）
1. 完成项目的 Plan 方案与分层 AGENTS.md，提交入库
2. 至少并行运行两个 Agent 完成两个模块并成功合并通过测试
3. 用 /review 完成一轮全项目审查并修复全部高优问题
4. 向 Cloud 提交至少一个收尾任务并合并其 PR
5. （选做高级项）用 /goal 发起「为项目补齐端到端测试」的长任务

## 课后作业与结课评估
1. 把课堂上未完成的阶段继续做完，最终部署上线或本地长期可用
2. 提交一份《我的 Codex 工作流手册》：包含个人启动参数习惯、AGENTS.md 模板、常用 Skill 清单、异步委派模板四部分
3. 结课评估标准：功能完整性 / 工作流规范性 / 安全红线遵守情况 / 手册可复用性四个维度打分
