# 第 8 课：综合实战——从零构建静态网站（30 分钟）

**教学目标**：
1. 综合运用前七课全部技能（Plan 模式 → AGENTS.md → Worktree 并行 → /review 质量把关 → 云端异步收尾），交付一个完整静态网站
2. 掌握多 Agent 并行开发的「先约定接口、各做各的、最后拼装」方法论
3. 建立「AI 能写代码，但你得知道要什么」的产品判断意识
4. 理解 Codex 与 Claude Code 的组合策略，形成自己的双工流心智模型

## 时间分配与内容大纲

> **组织提示**：本课课堂以五阶段路线图的推演与关键决策点讲解为主，完整的动手开发作为课后毕业实战延续推进。

### 一、项目发布与全局规划（5分钟）
1. **实战项目公布：个人静态网站**——每位学员自选主题（个人作品集 / 技术博客 / 产品落地页 / 小工具展示页等），用 AI 从零生成一个可部署的静态站点
2. **选型理由讲解**：Next.js 15 + Tailwind CSS + Markdown 内容 / 纯前端无后端 / 部署 Vercel 或 GitHub Pages——技术栈简洁，完整覆盖前端三件套（结构/样式/交互），且天然适合并行拆分
3. **学员自选主题环节**（2分钟快速头脑风暴）：
   - 鼓励选「能展示」的主题：个人简历站、技术博客、作品集、开源项目文档页、产品 Landing Page
   - 避免过复杂的需求：不需要后端、不需要登录、不需要数据库
   - **讲师展示 2~3 个参考案例**激发灵感
4. **阶段路线图**（呼应课程主线）：
   - 阶段一 Plan 模式规划（CLI）
   - 阶段二 Full Auto 基础搭建（CLI）
   - 阶段三 三 Agent 并行开发（App + Worktree）
   - 阶段四 合并与 /review 测试（CLI）
   - 阶段五 异步优化与部署（Cloud）

### 二、阶段一二：Plan 规划与骨架搭建（6分钟）
1. **Plan 模式发需求**：Shift+Tab 进入计划模式，产出技术方案与项目结构
   - 追问示范：「你的主题内容用 Markdown 还是硬编码？需要暗色模式切换吗？部署到 Vercel 还是 GitHub Pages？」——追问力 = 判断力的体现
2. **生成 AGENTS.md**：全局一份 + 组件版 + 内容/样式版；把页面结构约定全部写进去（本课成败关键，第 4 课技能直接应用）
3. **Full Auto 初始化骨架**：create-next-app + Tailwind 配置 + 基础布局组件 + 首页占位
4. **两条纪律**：
   - 骨架跑通 `npm run dev` 验证后立刻 commit——「每个里程碑都 commit 是保险不是洁癖」
   - 不给 AI 太大的任务：任务越具体输出越可控

### 三、阶段三：三 Agent 并行开发（7分钟）
学员分组跟做（讲师演示节奏）：
1. **开三个 Worktree 任务**（先约定接口再开工）：

   | Agent | 分支 | 范围 | 关键约定 |
   |-------|------|------|----------|
   | 1 | feat/content | 页面内容与路由 | 用约定的组件占位；导出结构化数据供组件消费 |
   | 2 | feat/components | 全部可复用组件 | 接受 props 接口约定；不直接改页面文件 |
   | 3 | feat/styling | 全局样式+响应式+暗色模式 | 只改 tailwind.config + 全局 CSS；组件用约定好的 class 命名 |

2. **等待期的正确姿势**：先审完成度高的分支（通常 components 最快出）/ 备好 Vercel 或 GitHub Pages 项目配置 / 想好部署域名
3. **经验强调**：并行最容易翻车的不是代码是「接口不一致」——10 分钟的约定省 1 小时的对齐

### 四、阶段四：合并集成与质量把关（6分钟）
1. **合并顺序有讲究**：底层优先——styling → components → content
2. 冲突处理交给 Codex 并给出仲裁原则：「样式层以 feat/styling 为准，组件层以 feat/components 为准」
3. **典型四类问题对照表**：
   - 组件 props 与实际传值不匹配 → 以 AGENTS.md 接口约定为准
   - 导入路径错误 → 检查 tsconfig aliases 与实际目录结构
   - Tailwind class 冲突或未生效 → 确认 content 配置覆盖范围
   - 暗色模式类名遗漏 → 统一使用约定的 dark: 前缀规范
4. `/review` 全项目审查 + 端到端验证（首页渲染 / 响应式断点 / 暗色模式 / 构建无报错）
5. 通过后 commit + tag v0.1.0

### 五、阶段五：云端异步收尾与部署（2分钟要点式）
1. 三类收尾任务批量丢 Cloud：README 编写 / SEO meta 信息补齐 / 性能优化（图片压缩、懒加载）——并行独立容器各出 PR
2. 部署二选一：
   - **Vercel**：`npx vercel` 一键部署，自动 CI/CD，域名自定义
   - **GitHub Pages**：`next export` 静态导出 + GitHub Actions 自动发布
3. 部署后验证清单：页面可访问 / 图片资源正常加载 / 移动端适配 / 暗色模式切换

### 六、常见陷阱总览与方法论沉淀（2分钟）
1. 教材八大陷阱速过（重点前三）：
   - Agent 改了不该改的文件 → worktree 隔离 + 合并时人工审查
   - 多 Agent 改同一配置冲突 → 共享配置文件只由一个 Agent 负责
   - 云端任务起不来 → setup 写全依赖；描述比本地详细 2~3 倍
2. **三条核心原则总结**（要求学员记笔记）：
   - 不要一次给 AI 太大的任务
   - 每一步都验证，出了问题再回头查成本更高
   - 最重要的能力不是写 prompt，是判断 AI 输出质量

### 七、双线开发者心智模型与结课（2分钟延伸）
1. 破除误解：Claude Code 也是多形态系统，差异在模型选型与生态侧重而非形态数量
2. benchmark 诚实解读：Codex 强在终端任务（Terminal-Bench 82.7% vs 69.4%）；Claude 强在真实 GitHub issue（SWE-Bench Pro 64.3% vs 58.6%）；1M 上下文都不是免费午餐（MRCR 检索率大幅下滑的诚实事实）
3. 双工流分工口诀：**Codex for keystroke（想清楚的快速执行），Claude Code for commits（没想清楚的一起想）**
4. 成本策略回顾：日常 GPT-5.6 luna，关键任务 GPT-5.6 terra；警惕 xhigh reasoning 默认档烧配额
5. 结课寄语：工具会换、模型会变，为自己积累的工作方法属于你自己；所有内容以官方 Changelog 为准持续更新认知

## 本课课堂演示清单
- Plan 模式产出方案到 AGENTS.md 定稿的完整链路
- 三 worktree 创建 → 并行进度监控 → 逐个回收合并实录（压缩演示）
- 合并后第一轮 `/review` 的真实输出讲解

## 学员动手实践任务（课后毕业实战延续完成）
1. 完成自己选定主题的 Plan 方案与分层 AGENTS.md，提交入库
2. 至少并行运行两个 Agent 完成两个模块并成功合并通过测试
3. 用 /review 完成一轮全项目审查并修复全部高优问题
4. 向 Cloud 提交至少一个收尾任务并合并其 PR
5. （选做高级项）用 /goal 发起「为项目补齐端到端测试」的长任务

## 课后作业与结课评估
1. 把课堂上未完成的阶段继续做完，最终部署上线或本地长期可用
2. 提交一份《我的 Codex 工作流手册》：包含个人启动参数习惯、AGENTS.md 模板、常用 Skill 清单、异步委派模板四部分
3. 结课评估标准：功能完整性 / 工作流规范性 / 安全红线遵守情况 / 手册可复用性四个维度打分
