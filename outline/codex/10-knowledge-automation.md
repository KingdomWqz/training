# 第 10 课：知识自动化流水线——捕获、消化与发布（30 分钟）

**教学目标**：
1. 用 Automations 搭建三条定时流水线：每日日记预处理、每周知识库体检、每周自动周报
2. 能用 /goal 发起「Inbox 清零」类跨 session 长目标，掌握完成判据的写法与适用判断
3. 打通「捕获 → AI 消化 → 沉淀 → 输出」全链路：移动端捕获、Cloud 异步整理、Quartz 发布
4. 建立知识库隐私红线意识，并把个人工作流沉淀成文档，直接服务第 11 课毕业实战

## 时间分配与内容大纲

### 一、导入：知识库的「新陈代谢」（3分钟）
1. 检验标准提问：一个知识库好不好，就看**半年后你还查不查它**
2. 三条流水线总览：捕获（Inbox / 移动端）→ 消化（Automations / /goal / Cloud）→ 输出（周报 / 发布）
3. 呼应第 7 课纪律：**先手动跑通再设自动化；无人值守场景禁用 full-access**

### 二、Automations 三条流水线（9分钟）
1. 前提回顾：App 保持运行、项目可访问、Git 仓库默认在独立 worktree 运行不影响本地（第 7 课）
2. **流水线 A · 每日日记预处理**：每天早上为当日每日笔记填充模板（昨日 commit 摘要 + 今日待办占位）
3. **流水线 B · 每周知识库体检**（重点演示）：扫描孤儿笔记（无入链）、失效双链、缺 frontmatter 的笔记 → 体检报告自动存入 Inbox
4. **流水线 C · 每周自动周报**：汇总本周新增笔记与每日笔记 → 生成周报草稿进 Triage 待审
5. 配置要点：**频率宁低勿高**（先每周验证价值再加密）；权限一律 workspace-write + AGENTS.md 约束；产出经 Triage 人工审阅再合入

### 三、/goal 与深度整理（7分钟）
1. 适用判断复述（第 7 课）：完成判据明确、跨多 session、愿意下放决策权
2. **示范 goal**：「Inbox 清零——每条笔记要么归位进 PARA 并建立至少一条双链，要么移入 Archives 并标记 status: archived；完成后输出分类统计报告」
3. 观察状态机：pursuing → paused（人工介入）→ achieved；budget-limited 何时出现、如何应对
4. **反面讨论**：为什么「把所有笔记重新组织一遍」是个坏 goal——判据模糊、无验收标准（呼应 Karpathy autoresearch 教训）

### 四、全链路实战：从捕获到发布（8分钟）
1. **捕获端**：手机 Obsidian 随手记进 Inbox；网页/聊天内容先落 Inbox 再说（剪藏土办法，示例方案不强求统一）
2. **消化端**：Cloud 任务挂到知识库私有仓库上异步整理（第 6 课能力）——「白天随手存，晚上 AI 整理好，早上看 diff」
3. **输出端**：Quartz 4 把 vault 变成个人数字花园网站；让 Codex 筛选「可公开」笔记并生成发布版
4. **隐私红线（重点强调）**：
   - 公开前必过审查清单：客户信息 / 密钥凭证 / 未发表观点 / 他人隐私
   - 让 Codex 先出一份「隐私扫描报告」，人工终审后再发布

### 五、沉淀与衔接毕业实战（3分钟）
1. 「知识库管理知识库」：把流水线配置、Skill 清单、AGENTS.md 全部写成笔记存进 vault
2. 课后撰写《我的知识工作流》（本课作业），**它就是第 11 课《我的 Codex 工作流手册》的核心素材**
3. 预告第 11 课：综合实战从零构建完整静态网站，前十课所有技能汇合

## 本课课堂演示清单

## 学员动手实践任务
1. 配置流水线 B（每周体检）并次日查看 Triage 报告
2. 用 /goal 发起一次 Inbox 清零（存量多则分批，先小后大）
3. （选做）本地跑通 Quartz 预览自己的 vault

## 课后作业
1. 完整运行一周三条流水线，记录 AI 整理结果的人工修正率，观察哪些规则要补进 AGENTS.md
2. 撰写《我的知识工作流》存入 vault：捕获习惯、整理规范、自动化配置、隐私清单四部分（第 11 课手册素材）
